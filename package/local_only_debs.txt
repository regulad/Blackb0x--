# .deb filenames (not package names — matches Blackb0x/Debs/'s own naming)
# that scripts/build_deb_cache.py includes directly from Blackb0x/Debs/
# without ever attempting real apt resolution for them at all — for
# packages that are genuinely dead upstream (no configured repo's Packages
# index carries them anymore, confirmed via a real "E: Unable to locate
# package" from apt itself, not assumed) but that this project already has
# a real, previously-recovered .deb for.
#
# This is NOT the same situation as com.ih8sn0w-squiffy-winocm.p0sixspwn
# (which DOES have a real Packages stanza — apt finds it fine — it just
# genuinely doesn't satisfy its own Depends: firmware constraint against
# this project's synthetic firmware version, which is correct, expected
# behavior for a firmware-version-gated package, not a dead-upstream one).
# That distinction is why this is a separate list from the ordinary
# packages.txt resolution flow, rather than one more tolerated warning.
#
# Entries here are still checked against Blackb0x/Misc/prebake_package_blacklist.txt
# like anything else in picklist.txt — see that file for why "essential"
# is listed there too (real, unmet Depends: on cydia, which is
# deliberately never bake-time-preinstalled).
essential_0-1_iphoneos-arm.deb

# net.tihmstar.etasonuntether — different reason than essential above, and
# different reason than com.ih8sn0w-squiffy-winocm.p0sixspwn's own
# still-live-but-firmware-gated KNOWN_EXPECTED_UNRESOLVABLE tolerance in
# build_deb_cache.py: this package's real Packages stanza on
# repo.tihmstar.net does exist, and — on a real device actually running
# firmware 8.4.1 (this package's own `Depends: firmware (= 8.4.1)`) —
# would genuinely resolve. It's here instead because that repo's live
# Packages/Packages.gz has been observed transiently out of sync with its
# own Release file (see Blackb0x/Misc/apt/net.tihmstar.list.disabled),
# making it an unreliable live dependency for something this project
# already has a real, previously-recovered .deb for. Real apt resolution
# is skipped entirely for it now (same as essential above) — it reaches
# the real device via this local file:// repo instead. This does NOT
# change how it actually gets *installed*, though: BakeRamdisk.cpp's
# stageEtasonatv() still extracts it directly and writes its dpkg status
# manually (see that function's own comment) — postinstall.sh's later
# real `apt-get install` of it (now that it appears in
# resolved_packages.txt) finds a package already at the exact same
# Status/Version stageEtasonatv() wrote, held (`Status: hold ok
# installed`), so it's expected to be a real, harmless no-op there, not a
# second, conflicting install path.
net.tihmstar.etasonuntether-1.3.1.deb
